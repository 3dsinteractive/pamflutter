# การเข้าสู่ระบบและออกจากระบบ

เมื่อผู้ใช้เข้าสู่ระบบหรือออกจากระบบของแอป ให้แจ้ง PAM ด้วย `Pam.userLogin()` และ `Pam.userLogout()` เพื่อให้ SDK ระบุตัวตนและเลือกฐานข้อมูลสำหรับบันทึกกิจกรรมได้ตรงกับสถานะผู้ใช้

ทั้งสองเมธอดใช้แจ้งสถานะให้ PAM ไม่ได้ตรวจสอบรหัสผ่านหรือจัดการการเข้าสู่ระบบของแอปแทนระบบสมาชิก

การแจ้ง login/logout ในตัวอย่างไม่ใช้ `await` เพื่อให้แอปทำงานต่อได้แม้ PAM Server ล่าช้าหรือไม่พร้อมใช้งาน SDK จัดลำดับคำขอผ่านคิวภายใน และจะเปลี่ยนสถานะเมื่อประมวลผลคำขอนั้น ส่วนการตรวจสอบ consent ยังคงใช้ `await` เพราะแอปต้องนำผลลัพธ์มาตัดสินใจ

---

## ฐานข้อมูลที่ใช้ตามสถานะผู้ใช้

SDK เลือกฐานข้อมูลจากค่าที่กำหนดใน `PamConfig` โดยอัตโนมัติ แอปจึงไม่ต้องเปลี่ยน config ทุกครั้งที่ผู้ใช้เข้าสู่ระบบหรือออกจากระบบ

| การกำหนด alias | ยังไม่ล็อกอิน | ล็อกอินแล้ว |
|---|---|---|
| กำหนดทั้งคู่ | `publicDBAlias` | `loginDBAlias` |
| กำหนดเฉพาะ `loginDBAlias` | ไม่ส่ง event | `loginDBAlias` |
| กำหนดเฉพาะ `publicDBAlias` | `publicDBAlias` | `publicDBAlias` |
| ว่างทั้งคู่ | ไม่ส่ง event | ไม่ส่ง event |

ไม่กำหนดหมายถึงส่งค่า empty string (`""`) เมื่อไม่มีฐานข้อมูลสำหรับสถานะปัจจุบัน SDK จะไม่ส่ง request และคืน `TRACKING_DISABLED` โดยไม่เข้าสู่ช่วงพักการติดตาม

เมื่อกำหนดเฉพาะ public DB การ login จะส่ง event `login` ครั้งเดียวและจดจำตัวตนสำหรับ event ถัดไป ส่วน logout จะส่ง `logout` และล้างตัวตน โดยไม่ย้ายฐานข้อมูลหรือทำขั้นตอนลบ push media สำหรับการย้าย DB

---

## Pam.userLogin(): แจ้งตัวตนผู้ใช้ที่เข้าสู่ระบบ

หลังแอปตรวจสอบการเข้าสู่ระบบสำเร็จ ให้ส่งตัวระบุตัวตนผู้ใช้ไปยัง PAM โดยค่าที่ส่งต้องตรงกับ `identityMatcher` ที่ตั้งค่าไว้ เช่น หากใช้ `customer` ให้ส่งรหัสลูกค้า

```dart
// เรียกหลังผู้ใช้เข้าสู่ระบบแอปสำเร็จ
// ตัวอย่างนี้ใช้ identityMatcher แบบ customer
Pam.userLogin('CUST-001');
```

SDK จะเปลี่ยนเป็นสถานะผู้ใช้ที่ระบุตัวตน และเลือก `loginDBAlias` หากกำหนดไว้ (มิฉะนั้นใช้ `publicDBAlias`) สำหรับกิจกรรมถัดไป แอปสามารถดำเนินการต่อได้โดยไม่ต้องรอผลจาก PAM Server

หากใช้ `identityProvider` ให้ระบบจัดการผู้ใช้ของแอปคืนตัวตนเดียวกับที่ส่งให้ `Pam.userLogin()` เพื่อป้องกันสถานะไม่ตรงกัน

---

## Pam.userLogout(): แจ้งว่าผู้ใช้ออกจากระบบ

เมื่อผู้ใช้ออกจากระบบแอป ให้แจ้ง PAM เพื่อล้างตัวตนผู้ใช้เดิมใน SDK และกลับมาใช้ `publicDBAlias` สำหรับกิจกรรมถัดไป

```dart
// เรียกในขั้นตอนออกจากระบบของแอป
Pam.userLogout();

// กิจกรรมถัดไปจะใช้ publicDBAlias
// และไม่ถูกส่งภายใต้ตัวตนผู้ใช้ที่ล็อกอินก่อนหน้านี้
```

แอปยังต้องล้าง session หรือ token ของระบบสมาชิกด้วยตนเอง หากใช้ `identityProvider` ให้ปรับสถานะของแอปเป็น `PamUserState.anonymous()` เมื่อออกจากระบบแล้ว

## Pam.reset(): ล้างข้อมูล PAM ในเครื่อง

หากต้องการล้างข้อมูลผู้ใช้ใน SDK ให้รอ `reset()` จบ แล้วใช้งานต่อได้ทันทีด้วย config เดิม ไม่ต้อง initialize ใหม่:

```dart
await Pam.reset();
```

คำสั่งนี้รอให้งานในคิวจบก่อนล้างข้อมูลผู้ใช้ของ PAM ทั้งใน secure storage, SharedPreferences และหน่วยความจำ ได้แก่ contact ทั้ง anonymous และ login, ตัวตนผู้ใช้, push token ที่บันทึกไว้, Device ID ที่แคชไว้, consent สำหรับ tracking, session และสถานะพัก tracking โดยไม่ล้างข้อมูลอื่นของแอป ส่วน config, alias ฐานข้อมูล, การตั้งค่า log และ callback ของแอปจะคงเดิม กิจกรรมถัดไปเลือกฐานข้อมูลสำหรับสถานะ anonymous ตาม config เดิม

หากล้าง storage ไม่สำเร็จ จะส่ง error กลับเพื่อให้แอปลองใหม่ โดยยังล้างสถานะในหน่วยความจำ รอ reset ให้สำเร็จก่อนเริ่มงานใหม่กับ PAM

คำสั่งนี้ไม่ส่ง logout ไม่ถอด push token บนเซิร์ฟเวอร์ และไม่ลบ contact หรือประวัติ tracking บนเซิร์ฟเวอร์ หากต้องการแจ้ง logout ให้เรียก `await Pam.userLogout()` ก่อน reset ส่วน Device ID ที่ระบบปฏิบัติการคืนมาอาจยังเป็นค่าเดิม และสิทธิ์ tracking หรือ notification ของระบบปฏิบัติการจะไม่ถูกเปลี่ยน

## เมื่อผู้ใช้เปลี่ยนบัญชี

แจ้งออกจากตัวตนเดิมและเข้าสู่ตัวตนใหม่ตามลำดับ โดยเรียกควบคู่กับขั้นตอนเปลี่ยนบัญชีในแอป:

```dart
// ออกจากตัวตนเดิมใน PAM
Pam.userLogout();

// หลังแอปเข้าสู่ระบบบัญชีใหม่สำเร็จ ให้แจ้งตัวตนใหม่
Pam.userLogin('CUST-002');
```

เมื่อเริ่มทำงานกับบัญชีใหม่ SDK จะใช้ `loginDBAlias` พร้อมตัวตนของผู้ใช้คนใหม่สำหรับกิจกรรมถัดไป
